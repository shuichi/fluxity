# 渋谷PLATEAUデータの再生成

このデモは[3D都市モデル（Project PLATEAU）渋谷区（2025年度）](https://www.geospatial.jp/ckan/dataset/plateau-13113-shibuya-ku-2025)の建築物・道路を加工して作成しています。標準製品仕様書5.0の公開CityGMLを用い、データの利用条件として[CC BY 4.0互換のPLATEAUサイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)に従います。コードのライセンスとは別に、データの出典・加工表記を維持してください。

## 再生成

Python 3.9で再生成と変換テストを検証しています。変換用依存ライブラリはWebアプリの実行時には不要です。

```sh
python3 -m venv /tmp/fluxity-plateau-venv
/tmp/fluxity-plateau-venv/bin/pip install -r scripts/requirements-plateau.txt
/tmp/fluxity-plateau-venv/bin/python scripts/import-plateau.py \
  --download --layout data/shibuya/layout.json
```

元CityGMLは `/tmp/fluxity-plateau-source`、元写真は `/tmp/fluxity-plateau-textures` に保存します。調査時のキャッシュ `/tmp/fluxity-53393596-bldg.gml` などを使う場合は、`--cache-dir /tmp` を追加します。写真キャッシュは `--texture-cache` で変更できます。取得後は `--download` を外してオフラインで再生成できます。通常の `npm run build` は元データの取得やPythonの実行を行いません。

生成物は `src/scenarios/data/shibuya-map.json` と `public/data/shibuya/` の `vertices.bin`、`indices.bin`、`appearance.bin`、`atlas-*.jpg`、`manifest.json` です。生のCityGMLや元JPEGはリポジトリに含めず、変換済みメッシュと写真アトラスを同梱します。検査用に `/tmp/fluxity-shibuya-polygons.json` も出力します。

```sh
/tmp/fluxity-plateau-venv/bin/python -m unittest discover \
  -s scripts -p 'test_import_plateau.py'
```

## 対象範囲と座標

交差点の基準点は北緯35.6595度、東経139.7005度です。周囲500m四方を描画用に取得し、シミュレーションは250m四方に限定しています。使用メッシュは53393585、53393586、53393595、53393596です。範囲を横切る建物は切断せず、建物全体を保持します。

元のEPSG:6697座標は緯度・経度・標高の順です。水平位置をJGD2011の平面直角座標第IX系（EPSG:6677）に変換し、原点の東距−12026.816802119605m、北距−37768.56112365173mを差し引きます。ローカル座標は東を+x、南を+z、上を+yとし、1単位を1mとします。

元のCityGMLと配布用メッシュを全440棟で照合しました。各棟の東西・南北・高さの寸法差は最大0.000017 mでした。これは座標変換後に頂点をfloat32で保存する際の差です。渋谷ヒカリエでは、元の形状の最低標高17.110 mから最高標高202.000 mまでの差と、描画メッシュの高さがともに184.890 mです。設計者が公表している最高高さは設計地盤面（GL）から182.50 mです。これらの値は高さをどこから測るかで異なります。[国土交通省の座標・高さの解説](https://www.mlit.go.jp/plateau/learning/tpc03-4/) · [日建設計による渋谷ヒカリエの概要](https://www.nikken.co.jp/ja/projects/transit_oriented_development/shibuya_hikarie.html)

建物はLOD2を優先し、存在しない場合のみLOD1にフォールバックします。`lod2Solid`の参照を解決し、同じポリゴンの重複とLODの重ね描きを避けます。屋根形状を含む3D形状は保持しますが、地面を平坦にするため建物ごとに最下点の標高を差し引きます。写真がある面には元データの写真を貼り、写真参照のない付属物・接地面などには材質色を維持します。地形、階段、駅構内、地下街、デッキの多層歩行は再現しません。

道路LOD2は車道1000・交差部1020・歩道2000・島3000の機能コードで区分します。表示と経路判定には同じ面を使用し、建物・交通島・指定された植栽領域を歩行可能範囲から除外します。横断歩道、駅前歩行者広場の補正、発生位置、信号位置は `data/shibuya/layout.json` で調整します。横断歩道の白線は道路面にクリップします。

横断歩道の白線は取り込み時に車道面から切り分けます。追加の区画線と着色舗装はシーンを読み込むときに、既存のアスファルトの三角形を分割して描画します。微小な高さの差で重ねる方法を避け、遠いOverview視点でも深度精度によるちらつきや白線の欠けが出ないようにしています。経路判定用の車道面は白線部分も含みます。

交差点へ入る4方向の路面は、5本の横断歩道を目印に空中写真と車道形状を照合して描き起こしました。`data/shibuya/road-markings.json` に、道玄坂のカーブに沿う中央線・車線境界線、北側の三角形の導流帯、6か所の赤系舗装、駅前バス乗り場の外周などをメートル単位で記録しています。高架に隠れる旧大山街道の区間は入口で白線の描画を止めています。車両の4経路は同じ座標系を使い、駅側では乗り場の両側を通ります。

白線の向き、曲がり、終点、着色区間は写真から判読し、線幅は国土交通省の都市部の標準値を参考にしました。配置と幅には撮影時点と画像の判読による誤差があります。[国土地理院の渋谷駅前の空中写真](https://maps.gsi.go.jp/#18/35.65950/139.70050/&base=seamlessphoto&ls=seamlessphoto&disp=1)・[国土交通省「区画線の設置様式について」](https://www.mlit.go.jp/road/sign/kijyun/pdf/19741226kukakusenn.pdf)

歩行者用の出入り口は計60か所あります。最初の5店舗と北側街路端を `data/shibuya/layout.json` に、追加の45店舗と9街路端を `data/shibuya/expanded-portals.json` に記録しています。店舗は歩道から接続できる地上階の壁面に設けたデモ用の戸口です。追加分は27の建物外周に分布し、幅は1.9〜3.5 mです。実在店舗の数や扉の位置は調査していません。

街路端は交差点から北・北西・西・東・南へ延びる5本の街路について、それぞれ両側の歩道に設けています。元からある北側の1か所では、歩行範囲の外側まで描画用の歩道が続きます。ほかの9か所では、交差点から到達できる歩道が車道・建物・舗装データの切れ目に接する手前を、シミュレーション上の出入り口としています。四角い範囲の外周上に歩道があっても、交差点から歩いて接続できない区間は使いません。地点番号と配置は[出入り口の地図](results/shibuya-portal-map.svg)で確認できます。

## 写真テクスチャ

CityGMLの`app:ParameterizedTexture`から、ポリゴンID、リングID、元画像の相対`imageURI`とUV座標を読み取ります。画像は同じPLATEAU公式配信の`udx/bldg/`から、対象440棟で使用する1,606枚だけを取得します。440棟すべてに写真があり、53,381面中46,173面にUV参照があります。残りの面は主に建物付属物・接地面です。

閉点と連続重複点を除去するときは、3D座標とUVに同じ元インデックスを適用します。穴はリングIDごとに対応させます。[元のUV原点は左下](https://www.mlit.go.jp/plateaudocument/toc9/toc9_05/toc9_05_02/)なので、変換時にVを反転し、画像の左上を原点とするUVへ一度だけ変換します。三角形の向きを補正しても頂点とUVの対応は保持します。

従来の40バイト頂点バッファとインデックスは変更せず、`appearance.bin`に頂点ごとの`float32 U, V, page`を12バイトで格納します。写真がない頂点は`page=-1`です。写真は2048×2048のJPEGアトラス5枚にまとめ、画像ごとに8ピクセルの余白と端の色の延長を付けています。

交差点に近い建物ほど高い解像度を残し、遠景を縮小してGPU使用量を抑えます。現在の出力では建物の最短距離75m以内の長辺上限708px、150m以内191px、遠景57pxで、元画像を拡大することはありません。ページ数が5枚以内になるまで、遠景を優先して縮小する規則で再生成します。

元写真は合計23,604,861バイト・約1.41億画素です。生成した5枚は合計6,084,655バイト、UVバッファは2,664,204バイトです。GPUのRGBA8テクスチャはミップマップ込み111,848,100バイト（約106.7MiB）です。実行時は同梱画像を使い、公式配信へ追加アクセスしません。元写真の解像度、撮影時点、写り込んだ影などは元データに依存します。

## 時点・品質・検証

「2025年度版」は公開データセットの整備年度です。各建物の作成日・調査年度は異なり、2024年作成の形状や2021年の属性を含みます。2025年・2026年の現況や工事状況を保証するものではありません。`surveyYear`はそのまま測量撮影日とは解釈しません。元データの建物ID・作成日・調査年度属性はマニフェストに記録しています。

取得元URL、実際に取得したXMLのSHA-256、サイズ、座標変換、レイアウトのSHA-256、生成バッファのSHA-256とLOD別建物数を `manifest.json` に記録します。配信APIのカタログ記載サイズと実ファイルのサイズに差があったため、実際のXMLを検査し、そのサイズとハッシュを固定しています。配信元のデータが変わった場合は変換を停止するので、差分を確認してから固定値を更新してください。

元写真も`appearanceSources`にURL・SHA-256・寸法・サイズ・アトラス内の配置を記録します。再生成時は既存の`manifest.json`と元写真のSHA-256を照合し、配信元やキャッシュの画像が変わっていれば停止します。この記録は再生成時にも残してください。

生成バッファのSHA-256は、アプリに同梱される `shibuya-map.json` の `mesh.vertexSha256` と `mesh.indexSha256` にも記録します。読み込み時に検証することで、公開更新の前後でキャッシュされた建物メッシュと歩行可能地図が混在することを防ぎます。

UVバッファと各写真アトラスにもSHA-256を持たせ、同じ世代の形状・UV・写真が揃っていることを読み込み時に検証します。

変換では凹多角形・穴・垂直面を三角形化し、float32化後の極小三角形を除外します。法線の長さ、三角形の向き、インデックス範囲、有限値、正規化した高さ、歩行可能面と建物の重複を検査します。13件の単体テストでは座標軸と縮尺、穴の面積保持、垂直面、LOD2参照解決、反転した立体の法線補正、閉点・重複点とUVの対応、V反転、穴のUV対応、向き補正時のUV保持、元画像のハッシュ照合などを確認します。生成数・除外数・残る元ポリゴンの非平面誤差はマニフェストの検証欄に記録します。

歩道モデルに含まれる植栽や敷地境界の細部、信号周期、歩行者需要にはデモ用の近似があります。測量成果や交通制御計画の代替として使用するものではありません。
