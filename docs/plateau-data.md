# 渋谷PLATEAUデータの再生成

このデモは[3D都市モデル（Project PLATEAU）渋谷区（2025年度）](https://www.geospatial.jp/ckan/dataset/plateau-13113-shibuya-ku-2025)の建築物・道路を加工して作成しています。標準製品仕様書5.0の公開CityGMLを用い、データの利用条件として[CC BY 4.0互換のPLATEAUサイトポリシー](https://www.mlit.go.jp/plateau/site-policy/)に従います。コードのライセンスとは別に、データの出典・加工表記を維持してください。

## 再生成

Python 3.9で再生成と変換テストを検証しています。変換用依存ライブラリはWebアプリの実行時には不要です。

```sh
python3 -m venv /tmp/fluxity-plateau-venv
/tmp/fluxity-plateau-venv/bin/pip install -r scripts/requirements-plateau.txt
/tmp/fluxity-plateau-venv/bin/python scripts/import-plateau.py \
  --download --layout data/shibuya/layout.json
```

元データは `/tmp/fluxity-plateau-source` に保存します。調査時のキャッシュ `/tmp/fluxity-53393596-bldg.gml` などを使う場合は、`--cache-dir /tmp` を追加します。取得後は `--download` を外してオフラインで再生成できます。通常の `npm run build` は元データの取得やPythonの実行を行いません。

生成物は `src/scenarios/data/shibuya-map.json` と `public/data/shibuya/` の `vertices.bin`、`indices.bin`、`manifest.json` です。生のCityGMLや写真はリポジトリに含めません。検査用に `/tmp/fluxity-shibuya-polygons.json` も出力します。

```sh
/tmp/fluxity-plateau-venv/bin/python -m unittest discover \
  -s scripts -p 'test_import_plateau.py'
```

## 対象範囲と座標

交差点の基準点は北緯35.6595度、東経139.7005度です。周囲500m四方を描画用に取得し、シミュレーションは250m四方に限定しています。使用メッシュは53393585、53393586、53393595、53393596です。範囲を横切る建物は切断せず、建物全体を保持します。

元のEPSG:6697座標は緯度・経度・標高の順です。水平位置をJGD2011の平面直角座標第IX系（EPSG:6677）に変換し、原点の東距−12026.816802119605m、北距−37768.56112365173mを差し引きます。ローカル座標は東を+x、南を+z、上を+yとし、1単位を1mとします。

建物はLOD2を優先し、存在しない場合のみLOD1にフォールバックします。`lod2Solid`の参照を解決し、同じポリゴンの重複とLODの重ね描きを避けます。屋根形状を含む3D形状は保持しますが、地面を平坦にするため建物ごとに最下点の標高を差し引きます。テクスチャは使用せず、建物面に材質色を付けています。地形、階段、駅構内、地下街、デッキの多層歩行は再現しません。

道路LOD2は車道1000・交差部1020・歩道2000・島3000の機能コードで区分します。表示と経路判定には同じ面を使用し、建物・交通島・指定された植栽領域を歩行可能範囲から除外します。横断歩道、駅前歩行者広場の補正、発生位置、信号位置は `data/shibuya/layout.json` で調整します。横断歩道の白線は道路面にクリップします。

地面・車道・歩道・白線は重複のない面に分割して描画します。微小な高さの差で重ねる方法を避け、遠いOverview視点でも深度精度によるちらつきや白線の欠けが出ないようにしています。経路判定用の車道面は白線部分も含みます。

## 時点・品質・検証

「2025年度版」は公開データセットの整備年度です。各建物の作成日・調査年度は異なり、2024年作成の形状や2021年の属性を含みます。2025年・2026年の現況や工事状況を保証するものではありません。`surveyYear`はそのまま測量撮影日とは解釈しません。元データの建物ID・作成日・調査年度属性はマニフェストに記録しています。

取得元URL、実際に取得したXMLのSHA-256、サイズ、座標変換、レイアウトのSHA-256、生成バッファのSHA-256とLOD別建物数を `manifest.json` に記録します。配信APIのカタログ記載サイズと実ファイルのサイズに差があったため、実際のXMLを検査し、そのサイズとハッシュを固定しています。配信元のデータが変わった場合は変換を停止するので、差分を確認してから固定値を更新してください。

生成バッファのSHA-256は、アプリに同梱される `shibuya-map.json` の `mesh.vertexSha256` と `mesh.indexSha256` にも記録します。読み込み時に検証することで、公開更新の前後でキャッシュされた建物メッシュと歩行可能地図が混在することを防ぎます。

変換では凹多角形・穴・垂直面を三角形化し、float32化後の極小三角形を除外します。法線の長さ、三角形の向き、インデックス範囲、有限値、正規化した高さ、歩行可能面と建物の重複を検査します。単体テストでは座標軸と縮尺、穴の面積保持、垂直面、LOD2参照解決、反転した立体の法線補正を確認します。生成数・除外数・残る元ポリゴンの非平面誤差はマニフェストの検証欄に記録します。

歩道モデルに含まれる植栽や敷地境界の細部、信号周期、歩行者需要にはデモ用の近似があります。測量成果や交通制御計画の代替として使用するものではありません。
