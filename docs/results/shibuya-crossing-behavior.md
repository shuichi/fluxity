# 渋谷の横断行動を1,000人で比較

[比較映像を再生（MP4、49秒）](shibuya-crossing-behavior.mp4)

この映像と以下の比較値は、ハチ公口の歩道と駅広場の接続を更新する前に記録した。シード42・自動信号の同じ街を、両列で同じ時刻・同じカメラ位置から描画した。上段は俯瞰、下段は近景。最初の四つの場面では、俯瞰の足元の印で対象者を追える。

| 映像の時間 | 左右の比較 | 着目点 |
| --- | --- | --- |
| 0〜10秒 | 左は通過、右は自撮り。両列とも拡張モデル | 同じ人が横断途中で立ち止まると、すぐ後ろの人がどう進路と歩調を変えるか。 |
| 10〜20秒 | 同じ自撮り。左は従来、右は拡張 | 減速して右手のスマートフォンに顔を向け、後続者が通り過ぎてから腕を下ろして歩き出す。 |
| 20〜30秒 | 同じ走者。左は従来、右は拡張 | 走者の加速、歩幅、周囲との速度差。シード42のRunnerでの実速度は最大2.92 m/s。 |
| 30〜40秒 | 同じ同行者。左は従来、右は拡張 | 同じ目的地を持つ2人の、開始8〜25秒の平均間隔は従来3.40 m、拡張0.83 m。 |
| 40〜49秒 | 左は混雑誘導なし、右はあり。両列とも拡張 | 五つの横断歩道で、新しく入る人の横位置が局所的に変わる。すでに渡っている人は選んだ通行位置を保つ。 |

Metal WebGPUでシミュレーションの各ステップを描画し、30 fpsで収録した。収録時の **Group** の初期グループはシード42で2人、0で3人、21で4人だった。現行版では操作パネルの **Crossing scene** で場面を選び、**Track participant** でその場面の出演者を追える。

専用Selfieプリセットは、同じ方向へ向かう後続者がいる歩行者を既存の旅程から選ぶ。このシードでは拡張方式の撮影者は25.77秒から減速し、26.77〜28.57秒に腕が上がり切った。同じ人がそのまま通過した場合との比較で、撮影者の2 m以内を通った2人の横位置は最大0.80 mと0.44 mずれ、別の通行人は最大0.44 m/s減速した。

## 同じ摂動を与えたときの歩行

1,000人、混合プリセット、自動信号、歩行速度設定1.35 m/s、回避強度1。最初の50秒（1,500ステップ）を観測した。同一シードの3条件で初期位置・向き・個人属性・目的地のハッシュが一致し、それぞれで走者・自撮り・同行グループが1件ずつ発生した。表の遭遇・切り返しは、少なくとも片方が横断歩道を占有する場面を対象とする。

| シード | 歩行モデル | 身体が接触した回数／近距離遭遇100件 | 左右の切り返し／対向遭遇100件 | 対岸への横断完了 |
| ---: | --- | ---: | ---: | ---: |
| 42 | 従来 | 3.71 | 5.40 | 433 |
| 42 | 拡張 | 1.76 | 1.17 | 463 |
| 42 | 拡張＋混雑誘導 | 2.15 | 1.64 | 439 |
| 137 | 従来 | 4.08 | 6.51 | 427 |
| 137 | 拡張 | 1.56 | 1.31 | 438 |
| 137 | 拡張＋混雑誘導 | 2.40 | 0.99 | 432 |

身体間の隙間が35 cm以内になった接近を1件とし、50 cmを超えて離れると次の遭遇として数える。接触は身体半径の和より内側に入ったときの接近速度も確認する。切り返しは、同じ対向者を前に1秒以内に左右の動きが反転した回数。横断完了は出発した歩道から別の歩道に着いた件数。全6条件で青点滅・赤での新規進入は0件だった。

全員が車道を離れるまで追うと、シード42の対岸への横断完了は従来444件・拡張475件、シード137は447件・452件だった。混雑誘導なしの拡張方式では最後の人が歩道に着いた時刻がシード42で62.73秒から66.07秒、137で61.63秒から63.33秒になった。歩行者が残っている間は車両への青を保留する。

計測時の標準設定は **Mixed / Enhanced、混雑誘導オフ** だった。混雑誘導をオンにすると、両シードで接触率が上がり、50秒以内の横断完了も少なくなった。俯瞰での変化は主に混み合った入口に限られた。

混合の撮影者が実際に止まった時間はシード42で2.47秒、137で2.23秒。どちらのシードでも、撮影のための減速・停止中に半径2 mへ入った通行人は0人だった。このため、撮影者の周りの回避は、後続者のいる専用Selfieプリセットで確認した。シード42で計測当時の標準設定を200秒間動かすと、2回の歩行者青で各行動が2件ずつ始まり、人口は1,000人に保たれた。

## 性能と再現

macOS arm64、Node v26.13.1。50秒の観測中、混雑誘導なしの拡張方式のCPU更新時間は95パーセンタイル9.94 ms（シード42）・9.77 ms（137）。混雑誘導ありでは9.87 ms・9.91 ms。実行中の他の負荷で変動する。別途、ChromeのMetal WebGPU・1,000人・Balanced・1280×800のブラウザ画面で、起動後の描画FPS表示を各モデル8回サンプリングし、どちらも60 fpsだった。

```sh
node --import tsx scripts/compare-crowd.ts --seed=42 --model=baseline --preset=mixed --density=off --seconds=50
node --import tsx scripts/compare-crowd.ts --seed=42 --model=enhanced --preset=mixed --density=off --seconds=50
node --import tsx scripts/compare-crowd.ts --seed=42 --model=enhanced --preset=mixed --density=on --seconds=50
```
